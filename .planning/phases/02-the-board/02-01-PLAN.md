**1. Create `src/utils/layers.js` — Layer management utility:**

Layer state shape: each layer is `{ id: string, name: string, type: 'sequencer'|'pad'|'preset', code: string, active: boolean }`.

Export these pure functions:
- `composeLayerCode(layers)` — Filter active layers, join their `.code` strings into a single `stack()` call. If 0 active, return `''`. If 1 active, return its code directly (no stack wrapper). If 2+, return `stack(\n  code1,\n  code2\n)`.
- `applyVolume(code, volume)` — If volume >= 1 return code unchanged. Otherwise wrap: `(${code}).gain(${volume.toFixed(2)})`.
- `addLayer(layers, newLayer)` — Return new array with newLayer appended. Deduplicate by id (if same id exists, replace it).
- `removeLayer(layers, layerId)` — Return new array without the layer matching layerId.
- `toggleSolo(layers, layerId)` — If the target layer is the only active one, un-solo (re-activate all). Otherwise, deactivate all layers except the target.
- `bpmToCps(bpm)` — Convert BPM to Strudel CPS: `bpm / 60 / 4` (4/4 time, 1 cycle = 1 bar).
- `bpmToHue(bpm)` — Map BPM to hue for slider color: 60 BPM = 220 (blue), 120 BPM = 140 (green), 180 BPM = 0 (red). Linear interpolation: `Math.round(220 - ((bpm - 60) / 120) * 220)`.

**2. Modify `src/utils/patterns.js` — Dynamic step count:**

- Export `STEP_COUNT` as the default (8) but accept `stepCount` parameter in `sequencerToPattern(grid, sounds, stepCount)`. When generating the struct string, slice each row to `stepCount` entries: `row.slice(0, stepCount).map(...)`.
- Export `DEFAULT_GRID` using 16 columns (max): `SOUNDS.map(() => Array(16).fill(false))`. This way the grid state always has 16 entries per row, and we just display/use the first `stepCount` of them. No resize function needed -- the data is always 16, the view shows 8 or 16.
- Export `resizeGrid(grid, newStepCount)` — NOT needed if grid is always 16 wide. But export a `STEP_OPTIONS` constant: `[8, 16]` for the segmented control.

**4. Refactor `src/App.jsx` — Layer state architecture:**

New state:
- `const [layers, setLayers] = useState([])` — Array of layer objects
- `const [bpm, setBpm] = useState(120)` — BPM (default 120)
- `const [volume, setVolume] = useState(1)` — Master volume (0-1)
- `const [stepCount, setStepCount] = useState(8)` — 8 or 16 steps
- Keep `grid` state but initialize with 16-wide rows: `DEFAULT_GRID` (updated)
- Keep `isPlaying`, `audioReady`, `audioLoading`, `audioError`

New evaluate flow:
- Create `evaluateAllLayers(currentLayers, currentVolume)` function that:
  1. Calls `composeLayerCode(currentLayers)` to get combined code
  2. If empty, calls `hush()` and sets `isPlaying(false)`, returns
  3. Calls `applyVolume(code, currentVolume)` to wrap with gain
  4. Calls `evaluate(finalCode)`
  5. Sets `isPlaying(true)`

Sequencer integration with layers:
- When sequencer grid changes (handleToggleCell), generate the pattern via `sequencerToPattern(grid, SOUNDS, stepCount)` and update or add a layer with `id: 'sequencer'`, `name: 'Sequencer'`, `type: 'sequencer'`. Then call `evaluateAllLayers` with the updated layers.
- When Play is pressed: same as above -- generate sequencer pattern from grid, set it as the sequencer layer, evaluate all.
- When Stop is pressed: `hush()`, `setIsPlaying(false)`, but keep layers (stop doesn't clear).
- **HUSH behavior (discretion: clear everything):** `hush()`, `setLayers([])`, `setIsPlaying(false)`. This is the panic button -- nukes everything. Per research recommendation: "Kids need HUSH to mean make it all go away."

Pad integration with layers:
- When a pad is tapped, add it as a layer: `addLayer(layers, { id: pad.id.toString(), name: pad.label, type: 'pad', code: pad.pattern, active: true })`. Then evaluate all layers. This replaces the old "pad replaces playback" behavior with the new layering system.

BPM change handler:
- `handleBpmChange(newBpm)`: Update state, then call `evaluate(\`setcps(${bpmToCps(newBpm)})\`)`. This is lightweight -- no pattern reparse. Do NOT throttle BPM (setcps is cheap per research).

Volume change handler:
- `handleVolumeChange(newVolume)`: Update state, then re-evaluate all layers with new volume. **Throttle this** to ~100ms using a ref-based approach since volume changes require full pattern re-evaluate. Use `useRef` for a throttle timer.

Step count change handler:
- `handleStepCountChange(newCount)`: Update stepCount state. If playing, re-evaluate with updated sequencer pattern using new stepCount. Grid data stays 16-wide, only the viewed/used portion changes.
