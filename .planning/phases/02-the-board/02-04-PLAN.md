**Bug 1 — BPM slider stops music (UAT test 1, major):**
The current `handleBpmChange` (line ~266-270) calls `evaluate(\`setcps(${bpmToCps(newBpm)})\`)` which replaces the current playing pattern with just a setcps command, killing the music.

Fix: After calling `evaluate(\`setcps(${bpmToCps(newBpm)})\`)`, immediately re-evaluate all layers so the music resumes at the new tempo. Use the functional `setLayers` pattern to get current layers:

```js
const handleBpmChange = (newBpm) => {
  setBpm(newBpm);
  evaluate(`setcps(${bpmToCps(newBpm)})`);
  // Re-evaluate all layers so music continues at new tempo
  if (isPlaying) {
    setLayers(currentLayers => {
      evaluateAllLayers(currentLayers, volume);
      return currentLayers; // Don't modify layers
    });
  }
};
```

Fix the 8/16 step toggle showing blank cells (UAT test 3, major).

**Root cause:** When stepCount changes from 8 to 16, the Sequencer component should show columns 9-16 from the grid. The grid data is always 16 wide. The issue is that React may not re-render Sequencer properly because the `grid` reference hasn't changed — only `stepCount` changed — and the `.slice(0, stepCount)` inside Sequencer's render may not trigger a fresh render if React's reconciliation doesn't detect a meaningful change.

**Fix approach — key prop on Sequencer:**
In App.jsx, add a `key` prop to the Sequencer component that includes `stepCount`. When `stepCount` changes, React will unmount/remount the component, guaranteeing a fresh render with the correct number of cells:

In App.jsx `renderTabContent`, change the Sequencer line from:
```jsx
<Sequencer grid={grid} onToggleCell={handleToggleCell} stepCount={stepCount} />
```
to:
```jsx
<Sequencer key={stepCount} grid={grid} onToggleCell={handleToggleCell} stepCount={stepCount} />
```

This is a one-character-level change in App.jsx (adding `key={stepCount}`).

**No changes needed in Sequencer.jsx** — the component already correctly slices `grid[rowIndex].slice(0, stepCount)` and sets `--step-count` CSS variable. The issue is purely a React re-render trigger, and the key prop solves it cleanly.
